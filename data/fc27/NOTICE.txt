EA SPORTS FC 27 database - provenance and licensing
===================================================

What this folder is
-------------------
The player/club/league database that The Gaffer runs on. Every JSON file here
was generated by:

    node tools/import_fc27.mjs

which is a BUILD-TIME tool. Playing the game does not need Node, npm or a
network connection: the runtime reads these files with the Python standard
library only (lib/fc27.py).

Upstream
--------
Generated from the FC 27 template tables bundled in `eafc-db-kit` 1.1.0:

    https://github.com/ViniMacacari/eafc-db-kit
    https://registry.npmjs.org/eafc-db-kit

Regenerating
------------
The upstream kit is ~208 MB and is deliberately NOT vendored here:

    npm pack eafc-db-kit
    mkdir -p /tmp/kit && tar xzf eafc-db-kit-*.tgz -C /tmp/kit
    node tools/import_fc27.mjs --kit /tmp/kit/package

Node >= 24 is what upstream declares; the importer was verified on Node 22.

Schema and mapping
------------------
fc27_meta.json records the generator, the as-of date, the counts, the 25-attribute
order and which EA field each attribute came from, the EA->PES position map, the
birthdate epoch (1582-10-14) and the preferred-foot convention (1 right, 2 left).

The six files players/ratings/positions/playpos/teamids/comps.json use the same
schema the existing transfer, growth, valuation and AI modules already read, so
those algorithms run on this data unchanged.

Data notes
----------
- Only real clubs are kept. National teams, Classic XIs, All-Star and marketing
  placeholder squads are excluded, so the top-rated active players are not
  legends from exhibition teams.
- A player has several club links in the source (club, national team, Classic,
  All-Star). Club assignment filters by league kind; taking the last link would
  put Messi at Argentina and Kane at "Bayern Muenchen Classic".
- Players with no real club remain in the database as free agents.
- Women's players and leagues are included and flagged (`women`, `gender`) so a
  career can filter them; they are not silently mixed into men's competitions.
- overallrating is EA's own value and is used directly. Recomputing it with the
  PES attribute weights would give a different number, because the 25 attributes
  in ratings.json are mapped from EA's separate attribute set.
- TWO attribute sets ship. ratings.json holds the 25 PES attributes the existing
  algorithms read; that is a lossy projection which drops crossing, volleys,
  reactions, longshots, interceptions, vision, penalties, composure and
  slidingtackle, and blends agility into TightPossession. ea_attrs.json holds
  all 34 EA values raw and unblended - prefer it for match simulation. Every
  direct PES mapping was verified equal to its EA source field (0 mismatches).
- `marking` and `gkspeed` do not exist in FC 27; DefensiveAwareness maps from
  `defensiveawareness`. Contract data comes from the player record
  (`contractvaliduntil`, `wage`, `releaseclause`) because the template's
  career_playercontract table is empty.
- Stadium names come from `stadiums` + `teamstadiumlinks`; the `teams` table
  only carries a capacity number. Manager names come from `manager`
  (commonname, else firstname + surname); many are unnamed placeholders.
- `squad_meta.json` roles come from `teamplayerlinks.position`, which doubles
  as a squad role: 0..27 = in the starting XI (with an EA position),
  28 = substitute, 29 = reserve. Shirt numbers are `jerseynumber`.
- Cup names are not columns: they resolve from the localization bundle as
  `LeagueName_<id>` / `TrophyName_<id>`. `country_lock` is -1 for several
  licensed cups (DFB-Pokal, Coupe de France); that means "not locked in the
  data", not "unknown country", and is not guessed at.
- `trait1`/`trait2` are stored as raw bitflags. Their individual bit meanings
  are not documented in the template, so no interpretation is invented.
- Positions come in two granularities of the SAME 28-id enum. formations.json
  slots are side-specific (4 RCB, 6 LCB, 9 RDM, 24 RS) while
  players.preferredpositionN only ever holds the coarse central id (5 CB,
  10 CDM, 25 ST); only 12 of the 28 ids appear on any player. ea_positions.json
  therefore ships a `slotCompat` map collapsing a slot to the id a player can
  hold. Verified: raw-id comparison matches 5,889 of 7,887 designated starters;
  through the map it matches 7,887 of 7,887.
- National teams are extracted into national_teams.json (69 teams, 1,740
  capped players) from the international leagues 78 / 2136. contract.json's
  `natPos` references these ids; without the table those 69 ids resolved in
  neither clubs.json nor the legacy teamids map. They are deliberately kept out
  of clubs.json so club competitions cannot draw a national side.
- Career-logic tables added in r16 after sweeping all 268 upstream tables:
  `default_teamsheets` (captain + 7 set-piece takers, 717/717 clubs, every taker
  verified in-squad), `clubcoefficients`/`nationcoefficients`, `career_calendar`,
  `multiclubownership`, `mls_group_structure`, `competitionstadiumlinks`,
  `prevcompetitionstats`, `referee`/`leaguerefereelinks`, the career name pools
  and regen/youth attribute templates, `attributeprefpositionformula`,
  `attributecategorymap`, `starratingboundaries`, `playstyle_attribute_requirement`.
  The remaining non-empty tables are presentation-only (skins, crowds, kits,
  vanity, audio) and are deliberately not extracted.
- `ovr_weights.json` and `playstyles.json` reference EA's INTERNAL attribute
  enum, NOT the `ea_attrs.json` field order. This was tested, not assumed: the
  identity mapping ranks only 29% of players highest in their own position, and
  an unconstrained fit reached 48% with impossible assignments (a GK formula
  weighting freekickaccuracy while gkkicking sat outside it), contradicted by
  attributecategorymap. Five ids appear in no formula. The ids are therefore
  shipped raw and unmapped, with no rating-in-position helper. The star bands
  are rating-based and safe. `regen_templates.json` is keyed by field name.
- `career_calendar`'s absolute dates are a 2008 placeholder; only the month/day
  transfer windows are shipped. Youth template ages are months (140..176),
  regen ages are years (16..21). Regen name `groupid` is a language/region pool,
  not a nation id - no upstream table maps the two.
- Season state (points, fixtures, results, budgets, form, injuries) is NOT
  extracted: the game engine owns it in its own save. The template's standings
  are half-populated and would seed a career with contradictory numbers.
- Market value is not a column in FC 27 (only `wage` and `releaseclause`), so
  the engine derives it; market.py / revalue.py already implement valuation.
